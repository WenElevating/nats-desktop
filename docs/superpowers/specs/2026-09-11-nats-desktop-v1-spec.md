## 2. 背景

### 2.1 当前问题

NATS 官方明确不提供 GUI 客户端（nats-server discussion #7623），官方工具链只有 natscli（命令行）、nsc、nats-top（TUI）。社区现有 GUI 均不完整：

| 现有工具 | 问题 |
|---|---|
| NUI（667 stars，Wails+React） | 仅覆盖 CLI 约六成功能面；服务器监控、账户、指标管理仍在其 roadmap |
| thedataflows/nats-desktop（纯 Go Gio） | 功能面全但已停滞 7 个月（2026-02 后无提交），UI 质感受框架限制 |
| easy-nats（Rust egui） | 活跃但视觉风格局限于工程感，深浅主题质量一般 |
| NATS Surveyor | 定位 Prometheus 指标导出管道，需配 Grafana，非桌面客户端 |

### 2.2 问题影响

- 运维与开发人员日常操作（查流、浏览消息、看消费者状态、KV 调试、服务器巡检）必须记忆 CLI 命令与参数组合，操作成本高；
- 实时监控需另行搭建 Surveyor + Grafana 体系，个人与小型团队负担重；
- 新手学习 NATS 的入口门槛高，缺少可视化反馈；
- 带凭据的连接配置（context）只能在终端维护，无法直观校验。

### 2.3 建设原因

- natscli 的业务逻辑实际位于 nats.go、jsm.go、natscontext 三个独立库中，CLI 层仅为薄封装——桌面客户端可直接复用同一批库，以与 CLI 完全一致的行为获得全部能力，建设成本低、互通天然成立；
- 官方无 GUI 计划，社区存在明确空白，且最活跃竞品 NUI 恰好缺少监控运维能力，存在差异化空间；
- 用户（项目发起人）已于 2026-09-11 需求评审中确认立项：分期交付、开源产品定位。

## 3. 目标

### 3.1 主要目标

1. v1.0 覆盖 natscli 的核心功能面：连接管理、消息调试（发布/请求/订阅）、Streams、Consumers、KeyValue、对象存储、服务器监控运维（功能清单见 §4.1，逐项验收见 §19.1）。
2. 连接配置与 natscli 双向互通：应用能读取、创建、编辑 CLI 的 context 文件，反之 CLI 能使用应用创建的 context（AC-003 验证）。
3. 支持浅色、深色、跟随系统三态主题，切换即时生效且重启后保持（AC-020 验证）。
4. 高配与低配硬件均可正常使用：双档性能预算全部达标（§12，AC-023/AC-024 验证）。
5. 交互质量达到生产可用标准：常用操作 ≤3 次点击可达、点击到视觉反馈 ≤100ms、核心操作键盘可完成、无障碍扫描零 critical 违规（AC-022/AC-026 验证）。
6. 以开源产品标准交付：Windows 安装包与便携包、GitHub Releases 发布流程、SHA256 校验和、英文默认 + 简体中文完整语言包（AC-021/AC-028 及 §21 验证）。

### 3.2 非目标

- 不做 auth（operator/account/user/nkey 管理，nsc 替代品）——独立大子系统，规划于 v1.2；
- 不做 bench 压测、latency 测试、micro 服务管理、schema 注册表、errors 查询、audit、counter——规划于 v1.1 及以后版本；
- 不做多连接并行对比——v1.0 全局单一活跃连接（与 CLI 的 context 心智一致），多连接规划于 v1.3；
- 不做静默自动更新——v1.0 仅做启动时新版本检查、提示并引导下载（所选桌面框架无内建更新器）；
- 不做 macOS/Linux 正式支持——v1.0 仅提供 best-effort 构建（TODO-004）；
- 不做移动端；
- 不替代服务器侧监控体系（Surveyor/Grafana）——本产品是客户端调试与巡检工具；
- 不做消息的持久化存储或离线缓存——消息只在内存中呈现，重启即失。

## 5. 术语与定义

| 术语 | 定义 |
|---|---|
| NATS | 消息系统本体（nats-server），本客户端的连接目标 |
| JetStream | NATS 内置的持久化消息流子系统 |
| Stream | JetStream 中的消息流资源，按 subjects 配置捕获消息 |
| Consumer | JetStream 中对 Stream 的消费配置（拉/推、durable/ephemeral） |
| KV 桶 / 对象桶 | 基于 JetStream 实现的键值存储桶 / 对象存储桶 |
| Context | 一份命名的连接配置（URL、认证、TLS、JetStream 定位参数），以 JSON 文件存储于 CLI 约定目录，natscli 与本应用共用 |
| $SYS | NATS 系统主题空间，服务器监控请求与系统事件（advisory）通过它交互，需服务器开启 system 账户并授权 |
| Advisory | NATS 服务器发出的系统通知事件（如连接断开、JetStream 领导者变化） |
| RTT | 客户端到服务器的往返延迟（毫秒） |
| 订阅会话 | 应用内一次可暂停/恢复的订阅运行实例，拥有独立的消息缓冲与速率统计 |
| 危险操作分级 | 一级=确认对话框（可恢复或影响小）；二级=输入资源名称确认（不可逆或影响大） |
| 主题三态 | 界面外观模式：浅色（light）、深色（dark）、跟随系统（system） |
| ro / rw | 只读操作（仅查询）/ 读写操作（改变服务器状态） |
| 高配 / 低配 | 性能验证参考硬件档位，定义见 §12 |

## 6. 功能规格

## 6.1 应用框架与导航

### 功能描述

提供桌面应用的整体骨架：固定左侧导航栏（Dashboard、Messages、Streams、Consumers、KeyValue、Objects、Monitoring、Settings 八个入口，带 SVG 图标与文字标签）、全局连接切换器（侧栏顶部）、命令面板（Ctrl+K）、启动时新版本检查、系统托盘、多语言框架（英文默认、简体中文包）。

### 输入

- 用户在任意页面的导航点击、快捷键（Ctrl+K 唤起命令面板）；
- 应用启动事件（触发 context 加载、上次活跃连接恢复尝试、新版本检查）。

### 处理逻辑

```text
启动
 ↓
加载应用设置（§7.1 设置文件）；无设置时以默认值初始化
 ↓
读取 context 目录；存在上次的活跃 context 时自动尝试连接
 ↓
渲染侧栏与当前页面；订阅连接状态事件驱动全局状态条
 ↓
后台向 GitHub Releases 查询最新版本号，与当前版本比较
 ↓
用户导航：点击侧栏或命令面板选择目标页面，页面切换保持各自状态
```

### 输出

- 当前页面渲染；命令面板列表（页面导航、连接切换、高频动作）；
- 新版本提示（当远端版本号高于当前版本时，显示一次可关闭的通知，附跳转下载链接）；
- 托盘菜单（显示/隐藏窗口、退出）。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 设置文件损坏 | 当设置 JSON 解析失败时，系统必须重命名旧文件为 .bak 后以默认值启动，并记录 WARN 日志 |
| context 目录不存在 | 当首次运行无任何 context 时，系统必须进入连接引导界面，提示创建第一个 context |
| 新版本检查失败 | 当 GitHub API 请求失败或超时（5s）时，系统必须静默跳过本次检查，不影响任何功能 |
| 上次连接恢复失败 | 当自动恢复连接失败时，系统必须保持引导界面并展示失败原因，不得自动重试超过 1 次 |

## 6.2 连接与 Context 管理

### 功能描述

管理 NATS 连接配置（context）：列表、新建、编辑、复制、删除、校验、测试连接；维护全局单一活跃连接并向全应用提供连接状态。

### 输入

- 用户在 Settings 页的表单输入：名称、描述、服务器 URL、认证方式（用户名/密码、token、nkey 文件、creds 文件路径）、TLS（证书/私钥/CA 路径、tls_first）、JetStream 定位（domain、api_prefix、event_prefix）、inbox_prefix、socks_proxy、色彩标签；
- context 目录中的既有文件（与 natscli 共享，含 CLI 创建的内容）。

### 处理逻辑

```text
表单提交
 ↓
字段校验：URL 格式合法、名称非空且不含路径分隔符、文件路径存在性提示
 ↓
写入 context JSON 文件（字段与 §7.1 一致，与 CLI 同格式同目录）
 ↓
测试连接（可选）：以该配置建立临时连接，测量 RTT 并尝试 JetStream 可用性
 ↓
连接激活：用户选择某 context 后建立唯一活跃连接，断开旧连接
```

### 输出

- context 列表（名称、URL、认证方式摘要、活跃标记）；
- 活跃连接状态（状态机见 §10）与 RTT（Dashboard 与状态条展示）；
- 连接状态变化事件推送至全应用（§8.5）。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 认证失败 | 当服务器拒绝认证时，系统必须将连接状态置为 failed，在界面显示服务器返回的认证错误原文，不得自动重试 |
| URL 不可达 | 当连接超时（默认 5s）时，系统必须显示超时错误并保留用户输入的表单内容 |
| context 文件被外部修改 | 当检测到文件时间戳变化且用户正在编辑同一 context 时，系统必须提示冲突并让用户选择保留版本 |
| 删除活跃 context | 当用户删除当前活跃连接的 context 时，系统必须先断开连接再删除文件，并要求一级确认 |
| CLI 环境变量存在 | 当检测到 NATS_URL、NATS_CONTEXT 等 CLI 覆盖型环境变量时，系统必须在界面显示提示：应用不读取这些环境变量，以 context 文件为准 |

## 6.3 消息发布与请求

### 功能描述

提供 pub（发布）与 req（请求-应答）调试能力：编辑 subject、headers、payload，选择 JetStream 发布选项，发送并查看结果。

### 输入

- subject（必填）、headers（键值对，可多行）、payload（文本，等宽编辑器）、JetStream 发布开关（开启后可选超时、等待服务器 ACK）、请求超时时长（默认 5s，范围 1–60s）；
- 发布历史（本次运行期最近 20 条，含 subject/payload/时间/结果）。

### 处理逻辑

```text
用户点击发布（或快捷键 Ctrl+Enter）
 ↓
校验：subject 非空且不含空格；payload 为合法 UTF-8（二进制内容走十六进制编辑模式）
 ↓
按所选模式发送：核心发布（ fire-and-forget）或 JetStream 发布（等待 ACK）
 ↓
req 模式：等待单一响应，超时前到达则展示响应
 ↓
结果写入发布历史并在响应面板展示（subject、耗时、JetStream ACK 流/序列号）
```

### 输出

- 发布结果（成功/失败、耗时、JetStream 确认的 stream 与序列号）；
- req 响应（payload、headers、耗时；JSON 自动语法高亮，二进制显示十六进制预览）。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 无响应者 | 当 req 超时或服务器报告无响应者时，系统必须显示「无响应者/超时」及已等待时长 |
| payload 超大 | 当 payload 大于 1MB 时，系统必须显示大小警告并要求确认后发送；大于 8MB 时拒绝发送并提示服务器默认上限 |
| JetStream 发布被拒 | 当 ACK 带有错误（如无匹配 stream）时，系统必须原样显示错误码与说明文字 |
| 连接断开 | 当发送时连接处于非 connected 状态时，系统必须禁用发布按钮并提示当前连接状态 |

## 6.4 订阅会话

### 功能描述

提供多会话实时订阅：按主题（支持通配符）订阅，实时滚动展示收到的消息，支持暂停/恢复/清空、速率统计、JetStream 定位（从流内回放）与 trace 模式（消息路径追踪）。KV watch 与对象 watch（§6.8/§6.9）复用同一会话机制。

### 输入

- 订阅主题（必填，支持 `*` 与 `>` 通配符）、可选 header 过滤；
- 会话控制指令：暂停、恢复、清空、关闭；
- JetStream 定位参数（可选）：起始序列号、起始时间、仅新消息开关。

### 处理逻辑

```text
用户创建会话
 ↓
按 JetStream 定位参数（若有）回放历史消息，随后进入实时接收
 ↓
接收消息：每条记录 subject、序列号、headers、payload、时间戳、大小
 ↓
推送节流：每 100ms 或每批 500 条（先到为准）向界面推送一批
 ↓
缓冲管理：每会话环形缓冲保留最近 10,000 条；缓冲满时丢弃最旧并累加丢弃计数
 ↓
暂停时：停止界面推送但继续计数；恢复时从当前最新消息继续（不回补暂停期间消息）
```

### 输出

- 消息列表（虚拟化滚动，等宽字体，subject/payload 摘要，点击展开完整消息）；
- 会话状态条：实时速率（msg/s，1s 窗口）、累计条数、丢弃计数、暂停状态。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 洪峰流量 | 当消息速率超过界面可渲染能力时，系统必须按节流与丢弃规则保持界面可用，丢弃计数准确显示，进程不得无响应 |
| 会话主题非法 | 当订阅请求被服务器拒绝时，系统必须显示服务器错误原文并关闭该会话 |
| 连接断开重连 | 当连接进入 reconnecting 时，系统必须将会话标记为暂停接收；重连成功后自动恢复订阅并继续，期间消息不回补（除非使用 JetStream 定位） |
| payload 二进制 | 当消息体不可解析为 UTF-8 时，系统必须以十六进制预览展示并提供完整内容下载 |

## 6.5 Dashboard 总览

### 功能描述

展示当前连接集群的健康总览：服务器数量与状态、账户连接数、JetStream 容量与使用、RTT、最近系统事件（advisory）列表。

### 输入

- 活跃连接的系统主题请求结果（$SYS，见 §8.3）；
- 轮询间隔（默认 5s，设置可调 2–60s）。

### 处理逻辑

```text
进入 Dashboard（或轮询周期到达且窗口可见）
 ↓
并行发起：服务器 PING、账户统计、JetStream 健康、RTT 测量
 ↓
汇总渲染：卡片（服务器数/在线数、连接数、JS 内存与存储使用比、RTT）
 ↓
最近 advisory 列表（最多保留 100 条，新事件置顶）
```

### 输出

- 概览卡片组、advisory 列表（类型、时间、来源服务器、摘要）；
- 当无 $SYS 权限时显示明确的能力不可用说明（见异常情况）。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 无 $SYS 权限 | 当系统主题请求被拒绝或无响应时，系统必须将监控卡片替换为「当前账户无系统监控权限」说明，其余功能不受影响 |
| 部分服务器超时 | 当集群中部分节点未在 2s 内响应 PING 时，系统必须按节点逐一标记离线，其余节点数据正常展示 |
| 窗口不可见 | 当应用窗口最小化或失焦时，系统必须暂停轮询；恢复可见后立即执行一次刷新 |

## 6.6 Streams 管理

### 功能描述

JetStream Stream 的完整管理：列表与筛选、详情与统计、创建/编辑/复制/删除/封存/purge/删单条、消息浏览器（分页浏览与单条查看）、速率图、备份/恢复、集群运维入口。

### 输入

- 列表筛选条件（名称、subject 模糊匹配）；
- 创建/编辑表单：名称、subjects、存储（file/memory）、保留策略（闭集：limits/interest/workqueue）、limits 参数组（max_msgs/max_bytes/max_age/max_msgs_per_subject）、副本数、放置（placement）、镜像/源头配置；
- 消息浏览器参数：序列号范围、subject 过滤、每页条数（默认 50，可选 20/50/100/200）；
- 危险操作指令：删除（二级）、purge（一级）、删单条（一级）、封存（一级）。

### 处理逻辑

```text
列表查询
 ↓
读取全部 stream 元信息，计算展示列（名称、subjects、消息数、字节数、消费者数、
速率、副本状态、缺失副本标记）
 ↓
详情查看：元信息 + 状态（序列、时间戳、消费者数、缺失）+ 速率图（5min/15min/1h 窗口）
 ↓
消息浏览器：按序列区间分页拉取；点击单条展示 headers/payload 完整内容
 ↓
变更操作：按危险级别走对应确认流程（§6.12 确认策略）后执行，
成功 toast 反馈 + 列表刷新；失败展示服务器错误原文
```

### 输出

- Stream 列表（可排序列）、详情面板、消息浏览分页列表、速率时序图；
- 备份产物：用户选择的本地目录中生成备份文件（含确认进度与完成提示）；
- 操作结果反馈（成功/失败与服务器错误原文）。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| JetStream 不可用 | 当账户无 JetStream 或域配置错误时，系统必须显示 JetStream 不可用说明与排查建议（检查 domain/api_prefix），不得显示空列表误导用户 |
| 消息体超大 | 当单条消息大于 1MB 时，浏览器中仅展示元数据与十六进制预览，提供下载 |
| 删除二级确认不匹配 | 当输入的名称与目标 stream 不一致时，系统必须拒绝执行并保持对话框打开 |
| 备份中断 | 当备份过程中连接断开时，系统必须停止备份、保留已完成分片、标记备份不完整，不得生成声称完整的备份文件 |
| 恢复目标已存在 | 当恢复的目标 stream 名称已存在时，系统必须要求用户先确认覆盖语义（删除重建）后才继续 |

## 6.7 Consumers 管理

### 功能描述

JetStream Consumer 的完整管理：列表、详情与统计、创建/编辑/复制/删除/重置、暂停/恢复、拉取预览（next）、速率图。

### 输入

- 所属 stream 选择、列表筛选；
- 创建/编辑表单：durable 名称、投递模式（pull/push 闭集）、filter subjects、确认模式（explicit/none/all 闭集）、ack 超时、max_deliver、max_waiting/max_request 批量参数、重投策略、优先级组、回放策略（all/last/序列/时间/新消息闭集）；
- 拉取预览参数：批量（1–256）、是否自动 ack（默认否）。

### 处理逻辑

```text
列表查询 → 展示（名称、类型、待处理数、已投递未确认数、确认数、丢失数、
红位数、暂停状态、副本状态）
 ↓
拉取预览：从消费者拉取一批消息展示（headers/payload/序列/投递信息），
不自动 ack（除非用户显式开启）
 ↓
暂停/恢复：执行后立即刷新详情，卡片式开关反馈当前状态
 ↓
重置：一级确认后清空投递状态
```

### 输出

- 消费者列表、详情面板（含统计与速率图）、拉取预览消息卡片、操作反馈。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 消费者被外部删除 | 当操作时服务器报告不存在时，系统必须刷新列表并提示资源已不存在 |
| 暂停中的消费者执行拉取 | 当消费者处于暂停状态时，系统必须禁用拉取按钮并显示暂停原因与剩余暂停时长 |
| 表单参数越界 | 当 ack 超时或批量数超出服务器接受范围时，系统必须在表单内联显示范围说明，不发起请求 |

## 6.8 KeyValue

### 功能描述

KV 桶与键的完整管理：桶列表/详情/创建/编辑/删除，键浏览、历史查看、put/create/update/del/purge/revert/compact、watch 实时监听。

### 输入

- 桶配置：名称、历史保留数、TTL、最大字节数、副本数；
- 键操作：键名、值（文本编辑器）、put（无条件覆盖）、create（仅当不存在）、update（带期望修订版）、del（保留历史）、purge（彻底清除）、revert（回退到上一修订版）；
- watch：单键或整桶监听。

### 处理逻辑

```text
选择桶 → 分页浏览键（键名、当前修订版、值大小、最后修改时间）
 ↓
查看键：当前值 + 修订历史列表（每次修订的值、修订号、时间）
 ↓
写操作按所选语义执行；del 为一级确认（历史可查可 revert）；
删除桶为二级确认（输入桶名）
 ↓
watch：复用订阅会话机制（§6.4），变更实时滚动展示（PUT/DELETE 操作与修订号）
```

### 输出

- 桶列表、键分页列表、键详情与历史、watch 实时视图、操作反馈。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| create 冲突 | 当键已存在时 create 失败，系统必须显示冲突提示并引导改用 put 或查看现有值 |
| update 版本冲突 | 当期望修订版与当前不符时，系统必须显示冲突说明与最新修订版号，保留用户编辑内容 |
| revert 无历史 | 当键仅有一次修订时，系统必须禁用 revert 按钮并提示原因 |

## 6.9 对象存储

### 功能描述

对象桶与对象的管理：桶列表/详情/创建/编辑/删除/封存，对象浏览、上传/下载/删除、watch。

### 输入

- 桶配置：名称、最大字节数、副本数；
- 上传：本地文件选择（可多选）、可选重命名；
- 下载：目标目录选择。

### 处理逻辑

```text
选择桶 → 浏览对象（名称、大小、修改时间、分块数）
 ↓
上传：读取本地文件分片上传，显示进度条（已上传字节/总字节）与速率；
上传完成刷新列表
 ↓
下载：流式写盘，显示进度；完成后提供打开所在目录入口
 ↓
删除对象为一级确认；删除桶为二级确认（输入桶名）；封存桶为一级确认
```

### 输出

- 桶列表、对象列表、上传/下载进度、watch 实时视图、操作反馈。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 上传中断 | 当连接断开时，系统必须停止上传并标记该对象为不完整，不删除已完成分片，提示重试入口 |
| 磁盘空间不足 | 当下载目标磁盘剩余空间小于对象大小时，系统必须在开始前提示并阻止 |
| 桶已封存 | 当对封存桶执行写操作时，系统必须显示服务器错误原文并提示封存状态 |

## 6.10 服务器监控

### 功能描述

面向运维的监控视图：服务器列表与 info/ping、报表（CPU、内存、连接数、路由、网关、leafnode、JetStream 健康）、top 式连接明细表（可排序、可断开连接需一级确认）、系统事件流（advisory 订阅与过滤）、账户信息与统计报表、实时刷新。

### 输入

- 轮询间隔（默认 5s）与暂停开关；
- 事件流过滤条件（事件类型、正则匹配）；
- 连接表操作：排序键、断开指定连接（需相应服务器权限）。

### 处理逻辑

```text
进入监控页 → 请求集群服务器清单与各节点状态
 ↓
渲染服务器表（名称、版本、状态、uptime、CPU、内存、连接数、JS 角色）
 ↓
按用户选择展开节点报表与连接明细（分页 + 排序）
 ↓
事件流：订阅 $SYS 事件主题，按过滤条件实时展示（复用订阅会话机制）
 ↓
实时刷新：轮询周期到达且窗口可见时重新请求；节点级失败只标记该节点
```

### 输出

- 服务器表、节点报表、连接明细表、事件流视图、账户信息与统计面板。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 部分节点失联 | 当某节点请求超时（2s）时，系统必须将该节点标记为离线（红色状态），其余节点数据正常展示与刷新 |
| 断开连接无权限 | 当 kick 操作被拒绝时，系统必须显示服务器错误原文 |
| 事件洪水 | 当事件速率过高时，系统必须复用 §6.4 节流与丢弃规则，界面保持可用 |

## 8. 接口规格

## 8.1 NATS 服务器连接

| 项目 | 内容 |
|---|---|
| 接口名称 | NATS 客户端连接 |
| 协议 | NATS（TCP 文本协议），可选 TLS |
| 请求方式 | 双向消息 |
| 地址/Subject | context.url 指定的服务器（支持多地址逗号分隔与 `nats://`、`tls://` 前缀） |
| 版本 | NATS 协议 v1（当前服务器体系） |

### 8.1.1 认证方式（闭集）

用户名/密码、token、nkey、creds 文件（JWT+签名）、TLS 客户端证书。组合规则以服务器接受行为为准。

### 8.1.2 错误码（服务器下行错误，界面需原样可读展示）

| 错误码 | 名称 | 说明 | 处理方式 |
|---|---|---|---|
| authorization violation | 认证失效/过期 | 服务器下行错误 | 状态置 failed，展示原文，停止重连 |
| permissions violation | 账户受限 | 超出订阅/发布权限 | 对应操作失败提示，连接保持 |
| 503 | 无法处理 | 服务器过载 | 操作失败提示，可重试 |

## 9. 业务流程

## 9.1 正常流程（首次使用到日常巡检）

```text
安装并启动应用
 ↓
引导创建第一个 context（表单 + 测试连接）
 ↓
连接成功 → Dashboard 展示集群总览
 ↓
用户进入各功能页（Streams / Consumers / KV / Objects / Monitoring）
 ↓
查询类操作即时返回；变更操作按确认分级执行
 ↓
创建订阅会话实时观察消息
 ↓
关闭应用（连接断开，设置与会话配置留存）
```

## 9.2 异常流程（断线恢复）

```text
正常使用中
 ↓
网络中断 → 连接状态切换为 reconnecting（全局状态条 + 页面横幅）
 ↓
自动重连（客户端库退避策略）；期间操作被拦截并提示当前状态
 ↓
重连成功 → 状态恢复 connected，订阅会话自动恢复订阅，轮询恢复
 ↓
若认证失败/超过最大重连次数 → 状态 failed，横幅给出原因与「修改连接」入口
```

## 9.3 异常流程（危险操作）

```text
用户触发二级危险操作（如删除 stream）
 ↓
系统展示影响说明 + 名称输入框
 ↓
输入不匹配 → 拒绝执行，对话框保持
 ↓
输入匹配 → 执行 → 结果反馈（成功 toast / 失败展示服务器错误原文）
```

## 10. 状态机（连接状态）

```text
┌──────────────┐  用户选择 context   ┌────────────┐
│ disconnected │ ─────────────────→ │ connecting │
└──────────────┘                    └─────┬──────┘
       ↑                                  │ 连接成功
       │ 用户断开/关闭                 ┌──↓─────────┐
       │              网络中断         │ connected  │
       │            ┌────────────────→ └──┬─────────┘
       │            │                     │ 自动重连中
       │       ┌────┴──────────┐          │
       └────── │ reconnecting  │ ←────────┘
               └────┬──────────┘
                    │ 认证失败/超过最大重连次数
                    ↓
               ┌──────────┐   用户修正配置并重连
               │ failed   │ ───────────→ connecting
               └──────────┘
```

### 状态定义

| 状态 | 进入条件 | 退出条件 | 系统行为 |
|---|---|---|---|
| disconnected | 应用启动未连接；用户主动断开；关闭应用 | 用户选择 context 发起连接 | 各功能页显示「未连接」引导；发布/查询按钮禁用 |
| connecting | 发起连接 | 连接成功（→connected）；认证失败或超时（→failed） | 状态条显示连接中动画 |
| connected | 连接建立 | 网络中断（→reconnecting）；用户断开（→disconnected） | 全功能可用；RTT 周期展示；轮询与订阅正常 |
| reconnecting | 网络中断 | 重连成功（→connected）；超限（→failed） | 状态条橙色 + 页面顶部横幅；操作被拦截并提示 |
| failed | 认证失败；超过最大重连次数 | 用户修正配置重连（→connecting） | 状态条红色 + 横幅显示原因 + 「修改连接」入口；停止自动重连 |

## 11. 异常处理

| 场景 | 检测条件 | 系统行为 | 日志级别 |
|---|---|---|---|
| 网络断开 | 连接事件报告断开 | 状态切换 reconnecting，横幅提示，操作拦截 | WARN |
| 认证失败 | 连接阶段服务器拒绝 | 状态切换 failed，展示服务器原文，停止重连 | ERROR |
| 请求超时 | 请求超过设置的超时时长 | 操作失败提示 E-TIMEOUT，查询类可手动重试 | WARN |
| 部分服务器不可达 | 节点 PING 超 2s 无响应 | 该节点标记离线，其余节点数据正常 | WARN |
| JetStream 不可用 | JS API 返回不可用错误 | 显示排查指引，不显示空列表 | WARN |
| $SYS 无权限 | 系统主题无响应或被拒 | 监控区显示能力不可用说明 | INFO |
| 订阅洪峰 | 推送速率超过渲染能力 | 节流 + 环形缓冲丢弃最旧，丢弃计数准确显示 | WARN（丢弃>0 时） |
| 大消息/二进制 | payload 非 UTF-8 或 >1MB | 元数据 + 十六进制预览 + 下载入口 | INFO |
| 设置/日志写盘失败 | 文件写入返回错误 | 提示 E-IO-WRITE，会话内保持已生效设置 | ERROR |
| 配置文件读取失败 | context/设置文件打开或读取错误 | 提示 E-IO-READ 与路径；设置损坏时回退默认值启动 | ERROR |
| 活跃连接缺失 | 功能操作发起时无活跃连接 | 返回 E-NOT-CONNECTED，界面引导到连接管理 | INFO |
| 本地校验失败 | 表单参数不满足字段规则 | 返回 E-VALIDATION，表单内联定位错误字段 | INFO |
| 管理请求参数被拒 | JetStream API 返回 400 参数无效 | 表单内联展示服务器错误描述 | WARN |
| 内部异常 | 未捕获错误 | 错误边界捕获展示，进程不退出，记录上下文日志 | ERROR |

### 异常处理原则

1. 不允许异常导致进程直接退出。
2. 无法恢复的异常必须记录日志。
3. 网络异常应支持自动恢复时，应定义重试策略。
4. 数据异常不得影响后续正常数据处理。
5. 所有关键异常应包含必要上下文信息。

## 12. 性能规格

> 参考硬件双档（2026-09-11 设计评审确认）：
> **高配** = 8 核 CPU / 16GB 内存 / NVMe SSD / Windows 11；
> **低配** = 2 核 CPU / 4GB 内存 / HDD / Windows 10，GPU 加速禁用（模拟集显与远程桌面场景）。
> 典型负载 = 1 个活跃连接 + 1 个订阅会话 + 监控页轮询开启。

| 指标 | 要求（高配） | 要求（低配） | 测试条件 |
|---|---:|---:|---|
| 冷启动到可交互 | ≤ 2s | ≤ 4s | 安装后首次以外启动 |
| 常驻内存 | ≤ 300MB | ≤ 400MB | 典型负载持续 30 分钟 |
| 订阅会话持续吞吐 | 5,000 msg/s，界面丢帧 <5% | 1,000 msg/s，界面丢帧 <5% | 1KB 消息持续注入 60s |
| 列表加载 | 500 streams ≤ 500ms | 500 streams ≤ 1,500ms | 已连接集群 |
| 大列表滚动 | ≥ 60fps | ≥ 30fps | 10,000 streams 虚拟列表 |
| 操作视觉反馈 | ≤ 100ms | ≤ 100ms | 任意按钮点击到出现加载态/反馈 |
| 安装包体积 | ≤ 30MB | 同左 | Windows 安装包与便携包 |
| 会话推送批延迟 | ≤ 200ms | ≤ 200ms | 从消息到达到出现在列表（P95） |

### 12.1 稳定性

系统连续运行：

```text
目标：≥ 24 小时（典型负载 + 每分钟 1 次页面切换）
```

期间：

- 不允许进程崩溃
- 不允许持续内存增长（结束时内存较 1 小时点位增长 ≤ 10%）
- 不允许线程持续增长
- 不允许连接资源泄漏（重连后连接数回到稳定值）
- 不允许消息队列无限增长

## 16. 安全规格

### 16.1 加密

- 服务器连接支持 TLS（证书/私钥/CA、tls_first），由 context 配置；
- 应用与本地服务层通信为进程内通道，不经过网络。

### 16.2 身份认证

- 认证方式集合见 §8.1.1；凭证仅用于建立连接，不得写入应用日志；
- 崩溃报告默认关闭；开启时仅上报错误堆栈与应用版本，不上报连接目标、context 名称、消息内容。

### 16.3 数据完整性

- context 与设置文件为本地 JSON，无签名要求；应用写入时保持原子写（先写临时文件再替换），避免半写文件。

### 16.4 权限

- 凭证文件以 0600 权限明文存储于 CLI 约定目录——与 natscli 完全一致（互操作优先，README 与应用内文档必须明示该明文风险与磁盘加密建议）；
- 界面对凭证字段脱敏显示（密码/token 以掩码呈现，可临时显示）；
- 应用不申请、不使用操作系统凭据库（决策：互操作优先，记录于设计评审 2026-09-11）。

| 图标 | lucide SVG 线性图标，导航 16px / 线宽 1.75；全局禁 emoji |
| 图表 | 时序图与火花线用 uPlot；表格内火花线 + 详情页全尺寸图（5min/15min/1h 窗口切换） |

### 18.3 状态显示（与 §10 状态机一一对应）

| 状态 | UI 表现 |
|---|---|
| disconnected | 各页引导卡片「选择或创建连接」；操作按钮禁用 |
| connecting | 状态条旋转指示 |
| connected | 状态点绿色 + RTT 展示 |
| reconnecting | 状态点橙色 + 顶部横幅「连接中断，正在重连」 |
| failed | 状态点红色 + 横幅显示原因 + 修改连接按钮 |

### 18.4 控件行为

- **表格**：列排序、列显隐、列宽拖动并持久化；行点击进详情；虚拟滚动（大数据集不掉帧，§12）。
- **表单**：内联校验（错误定位到字段）；提交中按钮加载态；失败保留输入。
- **危险操作**：一级=确认对话框列出影响；二级=输入资源名称，不匹配不执行；危险区红色呈现并与常规按钮分离。
- **快捷键**：Ctrl+K 命令面板；Ctrl+Enter 发布消息；Enter 确认对话框；Esc 关闭对话框/面板；发布/订阅核心路径可键盘完成。

### 18.5 反馈与状态

| 场景 | UI 表现 |
|---|---|
| 加载中 | 骨架屏（列表）/按钮加载态；点击到反馈 ≤100ms（§12） |
| 空数据 | 引导文案（如「没有 stream，创建第一个」附动作入口） |
| 操作成功 | toast（含关键结果，如删除的 stream 名） |
| 操作失败 | toast + 可展开错误详情（服务器错误码原文） |
| 订阅丢弃 | 会话状态条显示「已丢弃 N 条」角标 |
| 语言/主题切换 | 即时生效，无需重启 |

## 22. 回滚方案

### 回滚条件

- 新版本启动崩溃率 >5%（崩溃报告或用户反馈渠道）；
- 核心功能（连接、发布、订阅、流管理）不可用且无规避方案；
- context/设置文件出现破坏性写入（CLI 无法读取应用产出的 context）。

### 回滚方式

```text
新版本发布（GitHub Releases）
 ↓
发现严重问题（回滚条件之一）
 ↓
下架/撤回该 Release 资产，标记 pre-release 或撤回
 ↓
用户安装上一稳定版本（安装包保留于 Releases 历史）
 ↓
确认：context/设置文件向后兼容（应用只写 §7.1 约定字段，不引入旧版无法解析的结构）
 ↓
公告与修复版本跟进
```

> 桌面应用无服务端可回滚：数据兼容性由「不写私有字段进 context、设置文件新增字段可选」保证，任何版本可回退安装而不丢配置。
